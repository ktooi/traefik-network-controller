# プロンプト: 仕様駆動のレビュー

Traefik Network Controller の `<変更・差分・リリース>` を、`AGENTS.md`、正本 `SPEC.md`、schema、実際の CLI、`TESTING.md` に照らしてレビューしてください。説明文だけで設計を承認せず、実挙動と証拠を確認します。

## レビュー手順

1. コード変更と主張を要件 ID・受入項目に対応させます。実装／仕様／文書の食い違いを示し、都合の良い側を黙って選びません。
2. 正確な対象とネットワークの検証から所有権、猶予、停止中を含む全参照、直前検査、Docker 変更、台帳保存、変更後確認まで追います。リスクに関係する拒否と部分失敗を確認します。
3. 対象／network／endpoint の置換、手動／不明接続、破損／消失／symlink 状態、停止中参照、観測中断、保護、未使用の準備、切断後の収束、アプリ復帰、古い／改変された計画、外部競合の限界を確認します。
4. prepare が指定アプリだけに限定され、retire が自動切断と明確に別であることを確認します。現契約では自動削除、Force=true、他コンテナ切断、リモート切替、付随的な Socket Proxy 拡権は認めません。
5. 実 help／capabilities／schema／終了意味を例・プロンプト・スキルと照合し、英日整合と echo 例を確認します。新しいエージェントが架空コマンド、無許可の副作用、機密漏えいなしに作業できるか評価します。
6. 実行済みと、提供したが未実行の検証を分けます。実検証は許可された使い捨て Engine に限り、コンパイル／モックを Docker の実挙動、通信、全経路分離の証明としません。

## 報告

具体的な指摘を重要度順に、対象ファイル／動作、SPEC ID、発生条件、影響、限定した修正とともに示してください。実際の検証と blocked／未実施を記載します。不具合が見つからなければ確認範囲と限界付きで示します。修正が許可されていれば確認した問題を直して影響範囲を再検証し、不適合を適合に見せるためだけに要件を書き換えません。
