# プロンプト: アプリのエッジ廃止

導入済み契約と、利用可能なら運用スキルで指定アプリのエッジを廃止してください。`SPEC.md`、`docs/cli.ja.md`、`docs/operations.ja.md` を読みます。Traefik だけの自動切断と、空のネットワークを削除する明示的な `retire APP` を区別します。

## 入力

- アプリ／エッジ: `<app / traefik_app_<app>。例は echo>`。
- アプリ／controller の Compose パスと project: `<値>`。
- 目的: `<未使用エッジだけ削除 | アプリコンテナとエッジを廃止>`。
- データ保持: `<別指示がなければ volume を保持>`。
- 許可済み削除とデプロイ調整: `<範囲>`。

## 指示

1. version／help／capabilities と対象／network ID、保護、実接続、停止中も含む全参照を確認します。HTTP 失敗、stop、die、unhealthy から廃止を推定しません。
2. 具体的な network／container への作用、データ保持、並行操作の調整を示し、既存の許可を維持します。エッジ削除だけの依頼でアプリコンテナが残る場合、無許可で消さず blocker を示します。
3. 対象アプリの新規デプロイ／起動／接続を調整します。アプリ削除が範囲内なら既存 project を使い、データ削除を意図しない限り `down` に `-v` を付けません。無関係なコンテナを消しません。
4. `retire APP` を実行します。明示的な廃止は unowned でも正しい未使用エッジを対象にできますが、対象／属性／保護／参照の検査は必要です。強制切断は使わず、削除の出力 operation は `remove` です。
5. 指定エッジの不在、無関係な固定／アプリネットワークの維持、保持データを確認します。部分失敗では詳細と現状を読み、再試行を判断します。

prune、直接の強制切断、台帳編集、保護解除で拒否を迂回しません。自動 cleanup の有効化だけが目的なら、ポリシー／所有権／猶予の手順を使います。自動切断ではネットワークは残ります。SCOPE-002–005、OWN-002–004、LIFE-002–007、PLAN-005 と AC-04/06/09/13/17 に対応させます。
