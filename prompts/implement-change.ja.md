# プロンプト: 仕様駆動の実装

Traefik Network Controller に依頼した変更を実装してください。編集前に `AGENTS.md`、正本の `SPEC.md`、CLI／schema、対象コード、`TESTING.md` を読みます。コード／コメント／識別子は英語とし、日本語文書も同期します。変更内容: `<具体的な問題と望む動作>`。

## 手順

1. 現状の動作、対象の SPEC ID と受入項目を特定します。契約内の不具合修正か契約変更かを示し、実装を推定せず読みます。
2. 契約変更なら先に SPEC に条件、権限、失敗、並行操作の限界、移行影響を記載します。実装が難しいという理由だけで不変条件を弱めず、要件と検証済み実装を区別します。
3. daemon／once／plan／apply／明示的操作で共通ポリシーを実装します。対象／network／完全な ID、保護、gateway、停止中参照、永続 endpoint 所有権、保守的な失敗、猶予、ループ防止を維持します。自動処理でネットワーク削除、強制切断、他コンテナ操作を行いません。
4. 変更判断と拒否経路を実質的に検証し、テスト名／結果を受入 ID に対応させます。実環境は使い捨て Engine とし、本番ソケットに切り替えません。AGENTS.md／TESTING.md の format／build／test／Clippy を実施し、環境制約は明示して検証を削除・偽装しません。
5. 公開契約の変更は help、capabilities、schema、CLI 文書、例、英日 README／spec／operations、プロンプト、運用スキルを同期します。移行を明示しない限り既存名を維持し、例は echo／traefik_app_echo を使います。
6. 実際の差分と証拠を確認し、許可された修正を完成させます。ソース開発の依頼だけで導入・公開・拡権を行わず、未解決の権限が必要な場合は先に具体的成果物を用意します。

依存関係／toolchain／CI の変更は PUB-001–004 と AC-19／AC-20 に対応させます。再生成前に上流と内部のライセンス表示を確認し、`scripts/ci/check_licenses.py` を実行し、完全な共通 CI 検査を維持して各サービスの設定文書も同期します。公開準備は `prompts/prepare-release.ja.md` を使います。ソースの版は registry digest や push 成功の証拠ではありません。

## 完了報告

結果の動作、要件／受入項目との対応、変更ファイル、実コマンドと結果、互換性／移行、残るリスク、未実施検証を示してください。仕様、コンパイル、モック、実 Docker 通信を同じ証拠として扱わず、TESTING.md の証拠を超えて本番準備完了とは主張しません。
